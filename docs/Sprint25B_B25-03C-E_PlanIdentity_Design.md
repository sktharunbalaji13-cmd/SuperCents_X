## 1. Design goal

Define a **canonical plan identity** `PI` that:
- is reproducible from the *same trading decision* after restart,
- depends on **none** of: live market price, account equity, `candidateId`, `executionId`, `#<seq>`, or execution-time volume,
- is deterministic for the common structure-resolved plan and explicitly non-deterministic (identity undefined) for the live-fallback plan,
- requires the smallest possible persistence change, without redefining any existing field's semantics.

## 2. Recommendation: Option C — canonical plan payload (with a structure-resolved flag)

### 2.1 The identity

```
PI = ( symbol, side, magic,
       entryPolicy,  planEntryPrice,
       stopPolicy,   stopLoss,
       targetPolicy, takeProfit,
       structureResolved )
```

- `planEntryPrice` = the **structure-resolved** plan entry (`plan.entryPrice` from `ResolveEntryPrice` when it hit OB/FVG/liquidity), NOT the live Ask/Bid.
- `stopLoss` / `takeProfit` = the **structure-resolved** stop/target (`plan.stopLoss` / `plan.takeProfit`).
- `entryPolicy/stopPolicy/targetPolicy` = the resolution policies (config-derived, stable) — included for provenance and to disambiguate two plans that numerically collide but were generated by different structure types.
- `structureResolved` = `true` when entry, stop, AND target all resolved to structure; `false` when entry fell back to live price (`EntryPriceResolver.mqh:65` → `SYMBOL_BID`) or any resolver used a live/broker value.

### 2.2 Why this satisfies the requirement

| Requirement | Satisfied by |
|---|---|
| reproducible after restart | structure-resolved fields are deterministic (same bars → same OB/FVG/liquidity → same prices) |
| independent of live market price | `planEntryPrice` is structure-resolved, not `request.price`; the live-fallback case is **excluded** by `structureResolved=false` |
| independent of account equity | no equity term |
| independent of `candidateId` | no counter term |
| independent of `executionId`/`#<seq>` | no attempt term |
| independent of execution-time volume | no volume term |

### 2.3 The live-fallback rule (explicit)

When `structureResolved == false` (entry fell back to live Bid, or `ENTRY_CURRENT_PRICE`, or any resolver used a live/broker value), **`PI` is undefined**. Such plans have no reproducible identity, so:
- E must **BLOCK** them (cannot prove duplicate-safety), or treat them with a separate coarse rule (symbol+side+magic+time-window), never a precise MATCHED/NOT_FOUND.

This handles the assessment's finding that `plan.entryPrice` is "not universally stable": the flag makes instability *first-class* instead of pretending the numeric price is always an identity.

## 4. Minimal persistence change — **Option C1 (complete PI)** (to be authorized separately — NOT now)

The B25-03C-B INTENT payload currently is:
```
[0] decisionId | [1] symbol | [2] side | [3] requestedPrice | [4] requestedVolume | [5] sl | [6] tp | [7] magic
```
`[3] requestedPrice` stays **live** Ask/Bid (execution-truth lineage — unchanged, per the senior rejection of option (a)). `[1] symbol`, `[2] side`, `[7] magic`, `[5] sl` (= `plan.stopLoss`), `[6] tp` (= `plan.takeProfit`) are already persisted.

The required extension **appends the remainder of `PI`** (never redefines an existing field):
```
[8]  planEntryPrice     (structure-resolved plan entry; sentinel 0 when structureResolved=false)
[9]  structureResolved  (0/1)
[10] entryPolicy        (ENUM_ENTRY_POLICY, as int)
[11] stopPolicy         (ENUM_STOP_POLICY, as int)
[12] targetPolicy       (ENUM_TARGET_POLICY, as int)
```

**Why policies are persisted, not recovered from config:** the entry/stop/target policies are part of `PI` because two different structure types can resolve to the same numeric prices (e.g., an OB low coinciding with an FVG midpoint, with the same stop/target levels). Without the policies, E would treat two different plans as the same plan (false MATCHED → over-block) or be unable to prove which plan a record represents. Recovering the policies from *current* config is not sound — config may change across runs, so the durable record must carry the policies that actually generated it. (The same reasoning makes `TARGET_FIXED_RR` carry an implicit dependency on the stable `FixedRRTier` config; if a fixed-RR target is used, `structureResolved` should additionally require that the RR tier is stable, or the tier must be persisted too. The default policies — OB_RETEST / PROTECTED_POINT / OPPOSING_LIQUIDITY — are fully structure-resolved.)

### 4.1 Boundary of the change
- `CExecutionLedgerWriter.BeginExecution` payload build + `ParseIntentPayload` (B25-03C-B) — a **payload extension** (append `[8..12]`), a deliberate change requiring its own authorization (B25-03C-B is closed/pushed). It does NOT alter `requestedPrice` semantics.
- `TradeManager` call site — pass `plan.entryPrice`, the `structureResolved` flag, and the three policy enums as the new arguments. `request.price` is still passed unchanged.
- Frozen modules (`ExecutionIdentity`, `ExecutionTruth`, `ExecutionLedger`) and H6/D1 — **zero diff**.

### 4.2 Where the flag comes from
`structureResolved` is derivable at plan-build time: it is true iff `ResolveEntryPrice` returned a structure price (not the `SYMBOL_BID` fallback) AND `ResolveStopLoss`/`ResolveTakeProfit` returned structure values. This can be surfaced by the resolvers returning a `bool` out-param (a planner/`TradeManager` change, not a ledger change).

## 5. Cross-run duplicate detection with PI (E, future)

- Before send, fold the ledger (frozen `LedgerScan`) and compare `PI` of the current plan against every prior broker-visible INTENT's `PI`.
- Exact `PI` match (incl. `structureResolved=true`) → **MATCHED → BLOCK** (same plan already registered).
- Near match (same policies, one price within ε) → **AMBIAGUOUS → BLOCK**.
- No match → **NOT_FOUND → SEND** — now genuinely safe: `PI` is durable (unbounded ledger), deterministic, and non-recycled.
- `structureResolved=false` current plan → **BLOCK** (no identity).

This is the corrected, provably-safe NOT_FOUND → SEND: the negative case keys on a non-recycled, durable identity (not `candidateId`, not a bounded broker window, not the live price).
